Factory Inventory Management System

System Architecture & Technical Documentation

Overview

A full-stack demonstration application showcasing modern web development practices with Vue.js and FastAPI. The system provides comprehensive inventory management, order tracking, demand forecasting, and analytics capabilities for factory operations.

Note: This is a demo application using in-memory mock data. No database is required, making it perfect for development and demonstration purposes.

Frontend Architecture (Vue 3)

  • Router: Vue Router for client-side navigation across 6 views
  • Views: Dashboard, Inventory, Orders, Demand, Spending, Reports
  • API Client: Centralized axios instance in api.js
  • Composition API: Reactive state with refs and computed properties
  • Filtering System: Shared filters (Time Period, Warehouse, Category, Status)

Backend Architecture (FastAPI)

  • Entry Point: main.py - FastAPI application and all endpoints
  • Data Loading: mock_data.py - Loads JSON files at startup
  • Validation: Pydantic models ensure type safety and data validation
  • CORS: Configured for development (allows all origins)
  • Filtering: Query parameter-based filtering with helper functions

Data Structure

📄 inventory.json Inventory items with SKU, warehouse, quantity, costs
📄 orders.json Customer orders with items, status, dates, values
📄 demand_forecasts.json Demand predictions by product category
📄 backlog_items.json Items needing reorder with urgency levels
📄 spending.json Budget tracking and spending analytics
📄 transactions.json Transaction history for spending analysis
📄 purchase_orders.json Generated purchase orders for backlog items

Data Flow

1
User Interaction
User selects filters (warehouse, category, status, time period) or navigates to a view
↓
2
Vue Component
Component watches filter changes, triggers API call through api.js
↓
3
HTTP Request
Axios sends GET/POST request to FastAPI with query parameters
↓
4
FastAPI Endpoint
Endpoint receives request, validates parameters, applies filters to in-memory data
↓
5
Data Processing
Filter functions process data based on warehouse, category, status, and date ranges
↓
6
Pydantic Validation
Response data validated against Pydantic models, ensuring type safety
↓
7
JSON Response
FastAPI returns JSON response with filtered and validated data
↓
8
Vue Reactivity
Component updates reactive refs, computed properties recalculate, UI automatically updates

API Endpoints

Inventory Management

GET /api/inventory Query: warehouse, category
GET /api/inventory/{id} Get single inventory item by ID

Order Management

GET /api/orders Query: warehouse, category, status, month
GET /api/orders/{id} Get single order by ID

Analytics & Forecasting

GET /api/dashboard/summary Dashboard KPIs with all filters
GET /api/demand Demand forecasts (no filters)
GET /api/backlog Items needing reorder (no filters)

Spending Analytics

GET /api/spending/summary Budget overview and totals
GET /api/spending/monthly Monthly spending breakdown
GET /api/spending/categories Spending by category
GET /api/spending/transactions Recent transaction history

Purchase Orders

POST /api/purchase-orders Create new purchase order
GET /api/purchase-orders/{backlog_item_id} Get purchase order for backlog item

Task Management

GET /api/tasks Get all tasks
POST /api/tasks Create new task
PATCH /api/tasks/{id} Toggle task completion
DELETE /api/tasks/{id} Delete task

Development & Deployment

Quick Start: Run ./scripts/start.sh to start both servers, or start them individually with uv run python main.py (backend) and npm run dev (frontend).

Development Workflow

  • Hot Reload: Both frontend (Vite) and backend (Uvicorn) support hot reload
  • API Documentation: Auto-generated at http://localhost:8001/docs
  • Testing: Pytest for backend, testing framework ready for frontend
  • Data Changes: Edit JSON files in server/data/, restart backend to reload

Design Patterns

Frontend Patterns

  • Composition API: Modern Vue 3 reactive patterns with ref() and computed()
  • Shared State: Composables for cross-component state like filters
  • Reactive Data Flow: Raw data in refs, derived data in computed properties
  • Loading States: Consistent loading/error/data pattern across components

Backend Patterns

  • Type Safety: Pydantic models for all requests and responses
  • Functional Filtering: Reusable filter functions for common operations
  • Immutable Operations: Filtering creates new lists, never mutates source data
  • Quarter Support: Smart date filtering supporting both months and quarters
